Microsoft security · Agent protection map

Securing AI agents in the Microsoft ecosystem

Every protection layer in one view: who the agent is, what it can reach, how it is built, and how it is watched while it runs.

01 · Control plane

Microsoft Agent 365

The registry and governance layer in the Microsoft 365 admin center. It extends Entra, Defender and Purview to agents, so security teams keep working in the portals they already use.

  • Agent registry
  • Shadow-agent discovery
  • Entra identity per agent
  • Observability data feed
  • Included in Microsoft 365 E7
02

Three enforcement pillars

One per portal. Each acts on the agent's identity, behavior or data.

Microsoft Entra

Identity and access

  • Entra Agent ID

    A unique identity per agent. Blueprints define credentials and permissions for a class of agents.

  • Conditional Access + ID Protection

    User-style policies extended to agents, with real-time decisions on agent context, risk and resource sensitivity.

  • Identity governancePreview

    Named human sponsors, access packages as onboarding templates, and limits on how long access persists.

  • Agent inventory

    Agents with an Entra Agent ID, self-registered agents and shadow agents in one view.

  • Entra Internet Access (SASE)

    Monitors and blocks malicious or non-compliant agent traffic on user devices, Copilot Studio agents included.

Microsoft Defender

Threat protection

  • Security posture management

    Finds misconfigurations and exposure, and maps attack paths to critical assets.

  • Discovery across platforms

    Copilot Studio, Foundry, AWS Bedrock and GCP Vertex AI agents, plus local agents and MCP server configs.

  • Real-time runtime protection

    Inspects prompts, responses and tool calls, and blocks malicious tool invocations as the agent runs.

  • Threat protection for Foundry

    Defender for AI Services plan covers Foundry agents from development through runtime.

  • Detection, hunting, XDR

    Agent entity in incidents; Advanced Hunting over agent logs; signals correlated across email, endpoint, identity and cloud.

  • Local agent runtime protectionPreview

    Defender for Endpoint hooks into supported local agents on Windows endpoints.

Microsoft Purview

Data security and compliance

  • DSPM for AI

    Agent inventory, risk levels and oversharing insights in one posture view.

  • Sensitivity labels

    Agents inherit and honor labels; generated content keeps the source label.

  • Data loss prevention

    Blocks agents from accessing or sharing sensitive content, and keeps labeled files out of grounding.

  • Insider Risk + Communication Compliance

    Flags risky activity and policy violations in agent interactions.

  • Audit

    Agent interactions logged with the agent identity, for forensics and compliance.

  • Lifecycle, eDiscovery, Compliance Manager

    Retention for agent output, search and export of interactions, and assessments against AI regulations.

03

Build-time guardrails

Controls inside the platform where the agent is made.

Microsoft Foundry

Pro-code agents · Agent Service

  • Guardrails and content filters

    Risk detection set per agent, applied to inputs, tool calls and outputs.

  • Prompt Shields

    Detects direct jailbreaks and indirect prompt injection hidden in external content.

  • SpotlightingPreview

    Strengthens Prompt Shields against instructions hidden in documents and web pages. Microsoft reports attack success falling from over 50% to under 2% in tests.

  • Task adherencePreview

    Checks proposed tool calls and actions against the assigned task before they execute.

  • Managed identity, RBAC, OBO

    No shared secrets. Least-privilege roles define the blast radius; tools use managed or on-behalf-of auth.

  • Network isolationPreview

    Private endpoints and BYO VNet. Managed VNet for agent egress is in preview.

  • Keys, secrets, encryption

    Managed or bring-your-own Key Vault and customer-managed keys.

  • AI Red Teaming Agent + PyRIT

    Adversarial probing for jailbreaks and prompt attacks before launch and during production.

  • Tracing and monitoring

    Full conversation and tool-call traces through Application Insights.

Copilot Studio

Low-code agents · Power Platform admin

  • Power Platform data policies

    Allow or block knowledge sources, connectors, HTTP calls and skills in the same policy that governs apps and flows.

  • Managed Environments + sharing rules

    Environment groups and rules limit who can share agents and where they run.

  • Enforced Entra authentication

    Require sign-in on all interactions, and on connector, flow and action calls.

  • Secretless bot registration

    Federated Identity Credentials remove persisted secrets and certificates. New agents get an Entra agent identity.

  • Labels on knowledge and data

    Sensitivity labels show on SharePoint sources; Dataverse columns can be auto-labeled.

  • Maker alerts + protection status

    Warns before publishing when secure defaults change; shows each agent's threat-protection status.

  • Near-real-time runtime protection

    Copilot Studio sends planned actions to Defender, which approves or blocks them before they run.

04

Threat to control map

What stops each common agent risk.

1

Prompt injection

Stops it with: Prompt Shields and Spotlighting in Foundry; built-in Copilot Studio defenses.

Backed by: Defender inspects prompts, responses and tool calls at runtime.

2

Over-privileged agents

Stops it with: Entra Agent ID blueprints, Conditional Access, sponsors and time-limited access.

Backed by: Least-privilege RBAC and managed identities in Foundry.

3

Data oversharing and leaks

Stops it with: Purview sensitivity labels, DLP and DSPM for AI.

Backed by: Power Platform data policies and enforced authentication.

4

Shadow agents

Stops it with: Agent 365 registry and Entra's view of self-registered agents.

Backed by: Defender discovery across Microsoft, AWS and GCP platforms.

5

Tool misuse and scope drift

Stops it with: Task adherence checks plans before tool calls run.

Backed by: Defender blocks malicious invocations; Copilot Studio approve-or-block hook.

6

Exfiltration and unsafe egress

Stops it with: BYO or Managed VNet and private endpoints for Foundry agents.

Backed by: Entra Internet Access and Purview network DLP for unmanaged AI apps.

05

Beyond Microsoft-built agents

Third-party and local agents.

Onboard through Agent 365

Runtime security applies to Microsoft-built, supported third-party and local agents once they are onboarded.

Endpoint hooks for local agents

Defender for Endpoint runtime protection uses agent hooks. Claude Code and GitHub Copilot CLI are on the supported list. Preview.

Network layer for unmanaged AI

Purview network DLP over Entra Internet Access limits sensitive data going to consumer AI tools.

06

Before you rely on it

Three caveats.

Detection needs telemetry

Defender hunting and Purview audit only see agents that emit Agent 365 observability data. Check coverage before trusting an empty alert queue.

Preview status moves fast

Items tagged Preview were in preview in the sources used. Several Defender and Purview agent features are still preview. Confirm in the product docs.

Licensing and platform gaps

Agent 365 needs a qualifying Microsoft 365 plan or comes in E7. Some protections differ by platform; for example Prompt Shields block events are not yet recorded for Copilot Studio.
